# Wire's Balanced Craft From Nearby Chests — Native Hover Integration, 2026-11-09

## User goal
Remove independent 0.08-second hover checking. Use Valheim's actual native hover lifecycle to immediately activate chest/station connection effects only on a meaningful transition. Preserve multiplayer chest-title changes, dynamic container visuals, previous yellow color, tool/build-menu transitions and no independent per-frame Unity Update.

## Source evidence
- ValheimSOURCE/csharp/assembly_valheim/Player.cs:879 calls private UpdateHover() in vanilla Player.Update after checking ZNet ownership. Native private UpdateHover method (~2901-2912) sets m_hovering and m_hoveringCreature via FindHoverObject. Player.GetHoverObject (~4397) returns cached m_hovering. Verified exact method signatures with Mono.Cecil against actually installed assembly_valheim.dll: Player::UpdateHover(), Player::OnDestroy(), Player::SetLocalPlayer(), each exactly one method.
- Previous BCFNC Plugin.Start invoked InvokeRepeating(Poll, .5, .08) every 0.08 seconds even when idle; Poll performed ContainerRegistry.TickReconcile and ConnectionVisuals.Poll. ConnectionVisuals performed cheap hover/tool/build state comparison then heavyweight PollContext only on transitions, and moving-graph check every 0.25 sec if relevant. ContainerRegistry.TickReconcile only reconciled ONE known container every 0.25s, so prior code was NOT rescanning all 70 chests 12.5 times/second.

## Implementation
- NEW src/NativeHoverEvents.cs: Harmony postfix on vanilla Player.UpdateHover, calls ConnectionVisuals.HoverUpdated(local player) AFTER native raycast/cache update; no redundant raycast. Only cheap cache comparisons on vanilla game hover callback; detailed station/chest/refill/tool context discovery runs on true hover, build UI, equipped tool or graph invalidation change. Native full-method event runs every game frame, but there is no additional Unity Update component, no independent 0.08-second timer, no repeated raycasts.
- Plugin.Start now schedules ONLY `ReconcileRemoteChestNames()` at 0.25s for otherwise unobservable remote chest renames. Reuses ContainerRegistry.TickReconcile, a one-chest-at-a-time O(1) operation with its existing safeguards and private own next timer. Mod's own Plugin.Update remains enabled only when work is outstanding (visual animation, fade, pending chest indexing and MultiUserChest).
- Moving-container graph check remains in native hover hook but tests Time.time and actual moving status only every 0.25s while context active, preserving dynamic chest/station connections without a timer. It can set graph dirty and wake active animation driver if connections move.
- ConnectionVisuals.NotifyGraphChanged now marks `_contextCacheInvalid` instead of forcing `_lastHover=null`, so a route rename also updates the build-tool context even when hovered object is null; active context marks dirty with original lazy graph delay.
- Visual config OFF clears cached hover, tool and build state and marks invalid for reliable ON rebuild, preserving fading of old beams.
- Source-native lifecycle guards: Player.OnDestroy prefix calls ConnectionVisuals.Cleanup if local player is destroyed, avoiding stale beams while there is no Player.UpdateHover. Player.SetLocalPlayer postfix forces next hover context rebuild after world load/swap. These are finite lifecycle events, not per-frame polling.
- Previous golden-yellow particle color + cloned per-renderer HDR emissive material override and deterministic vanilla generic prefab selection are preserved unchanged. Version remains 0.1.11; no manifest/README/version or other mod changes.
