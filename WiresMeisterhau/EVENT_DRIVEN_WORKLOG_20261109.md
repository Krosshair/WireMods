# Wire's Meisterhau — event-driven delayed work fix, 2026-11-09

## Source evidence
- Previous `WiresMeisterhauPlugin.cs:103` Unity `Update()` ran EVERY rendered frame and called `ResolvePendingXp()` and `PruneOldHits()`. `ResolvePendingXp` returned immediately when no pending awards; `PruneOldHits` returned when `Time.time < NextPruneTime`, so actual cleanup only every 0.5s, but there was an unnecessary 60-160Hz wake/check and timer branch.
- The only pending bonus XP producer is `OnCounterSuccess(HitRecord)`: queued `PendingXpAwards.Add({ResolveAt=Time.time+0.05f})`; the only recent-hit producer is `RegisterActualPlayerHit()`: `RecentHits[target.GetInstanceID()] = record;`. Each is an exact discrete native hit/counter event. `GetRecentHit()` already verifies age <= vanilla parry window (0.25s), so cleanup timing beyond 0.75s is only dictionary hygiene, not gameplay eligibility.

## New design and implementation
- Removed `private void Update()` entirely; removed `NextPruneTime` and replaced periodic 0.5s cleanup with a one-shot scheduled callback after actual registered hits. No Update/FixedUpdate/LateUpdate, no coroutine, no interval poll.
- Successful counter schedules a single `MonoBehaviour.Invoke(nameof(ResolvePendingXpDue), ...)` at the earliest pending award deadline (original .05s game-time). Multiple success events share the pending invoke; after callback, ResolvePendingXp awards matured records and reschedules only if unprocessed records remain. New success deadlines cannot precede already queued old successful hits because all deadlines are now+.05s. Uses Unity scaled game time as existing Time.time did.
- Registered hit schedules `PruneHitsDue` at earliest record expiration (~0.751s), after which it prunes consumed or expired records and reschedules only if dictionary still contains live hit records. Multiple hits share a single prune callback. `RecentHits` still enforces 0.25s in GetRecentHit, unchanged.
- Explicit `_xpInvokePending` and `_hitPruneInvokePending` flags avoid depending on `IsInvoking` semantics inside a currently executing one-shot. `CancelInvoke` and clearing pending work/records on plugin OnDestroy protect teardown, source/unload and reload.
- No gameplay damage formulas, network sync, parry odds, XP multiplier, audio or visuals modified. No README, manifest, version bump or other mod changes. Existing branch has pre-existing .csproj modifications and .preEnngard file, untouched.
