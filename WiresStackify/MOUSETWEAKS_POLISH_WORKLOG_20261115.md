## Verified actual ROOT CAUSE of Shift+RMB auto-cancel
- From actual ValheimSOURCE/InventoryGui.cs::UpdateItemDrag (~line 815), after updating the dragged icon, vanilla does `if (ZInput.GetMouseButton(1) || JoyButtonB) SetupDragItem(null,null,1)`. This cancels the drag on the SAME right-click that the previous Stackify HalfPickup.OnRightClickItem patch had just started. Shift is NOT the cause. Native installed assembly_valheim.dll via Mono.Cecil: one `ZInput::GetMouseButton(System.Int32)` call in UpdateItemDrag, correct signatures for OnRightClickItem, SetupDragItem, OnRightDown, OnLeftDown.
- New `WiresStackify/src/HalfPickupGuard.cs`: Harmony transpiler replaces ONLY that one `GetMouseButton(int)` call in `InventoryGui.UpdateItemDrag` with a small wrapper. While Stackify has an item in the inventory cursor and inventory is visible, RMB no longer cancels it (RMB is reassigned to placing/distributing one by Mouse Tweaks). Outside that exact state, vanilla input behavior stays. Existing keyboard/scene/inventory cleanup untouched; no new Update/FixedUpdate/LateUpdate component. On unexpected game IL, warns and leaves vanilla untouched. `StackifyPlugin.Awake` already PatchAll(assembly); verified.
- `MouseControls.MovingKey` now explicitly checks physical ZInput.GetKey(KeyCode.W/A/S/D), NOT Shift, Ctrl or generic movement action bindings. In `InventoryGui.OnRightClickItem` prefix stationary Shift+RMB with stack>1 uses native SetupDragItem(item,inventory,ceil(stack/2)) to reserve half; while WASD held, native use-item pathway executes, preserving Shift+W+potion.
- New `s_initialPickupRightPress` prevents that initiating Shift+RMB from ALSO distributing items during the same continuous press. It resets when RMB released; a separate RMB press while holding places one, Shift+RMB places half. Right-drag moves one per newly entered (GRID,slot), including crossing player/container panels with identical coordinates.

## Mouse controls source fixes & safety
- Ctrl+left (single and held sweep) now uses helper MoveViaVanilla() with native InventoryGui.OnSelectedItem(...Modifier.Move). Without a container this drops whole stack; with container it moves/merges, native plays its own sound. Favorite item + favorite SLOT protection correct ONLY for player's slots; chest slots with same X,Y are not falsely treated as favorited. Hotbar number swap still bypasses favorite suppression intentionally, uses vanilla drag+drop; unchanged.
- Held RMB slot tracking formerly stored only Vector2i, so crossing between player/chest grids with same position silently skipped the slot. Tracks both grid identity and slot for RMB distribution and Ctrl-held sweeping.
- On double-click fill: previously first native LMB picked up full stack, so second LMB failed `DragItem == null` check. Second click now also recognizes held same item, clears cursor before completing source-side stack consolidation. Uses actual native `ItemData.IsSameType` (name/quality/worldLevel) instead of insufficient name+quality test; prevents mixing incompatible stack contents. One vanilla move SFX on successful merged fill; no SFX on failed/no-op.
- Right placing into occupied stack now clamps quantity to available target room BEFORE native Inventory.MoveItemToThis, because the actual private native Inventory.AddItem can partially consume items and return FALSE when amount exceeds available room. Prevents partial-success/no-sound/incorrect-cursor-state bug.
- Wheel DOWN while holding a reserved partial/half stack decrements held amount; stops drag precisely when reserved count reaches zero rather than allowing transfers beyond picked-up amount. Wheel UP while holding adds to held reserve as well as source stack. Both obey other-inventory-only routing and native inventory mutations. Source and destination positions read from actual InventoryGrid.m_elements; no extra inventory scanning per frame.
- Existing native m_moveItemEffects SFX for custom successful place, scroll, double-click fill preserved. Native Ctrl/hotbar transfers retain their own game sound. No new audio assets or fake samples, no duplicate success sounds intentionally.

## Smooth UI animation architecture & proper merge flights
- Read complete relevant Smooth UI `ItemAnimationSystem` and `DragAnimationSystem`, as well as `SmoothUIDriver`, and native InventoryGrid/InventoryGUI/Inventory. Smooth UI tracks same-instance moves via LastPositions/InFlight; new cloned destination via NotifyQuickTransfer (85ms) and native amount changes via existing PulseTimer (~160ms). Prior bridge only used newly created item identity, so after the FIRST scroll item into EMPTY slot, all further wheel ticks merged a stack and showed NO moving source icon; user found this very scuffed.
- Added WiresSmoothUI/src/QuickTransferEffects.cs: a short-lived image of the real item icon flies from SOURCE slot to destination occupied stack using SmoothUI's existing EaseOutCubic, 85ms, small landing scale/fade; at most 12 concurrent images, pooled/reused; no new MonoBehaviour/Update/coroutine, uses the EXISTING SmoothUIDriver's on-demand Tick only while flights exist, cleans on disable/GUI unload. No per-frame inventory scan.
- Added ItemAnimationSystem.NotifyStackTransfer(item,sourceWorld,destinationWorld) optional method, wired to quick visual flight; retains original native destination amount pulse, not fake move of entire stack. SmoothUIDriver now ticks QuickTransferEffects and includes Busy flag; RestoreEverything clears it. Other Smooth UI animation timing/behavior unchanged.
- Stackify SmoothUIBridge optionally resolves both `NotifyQuickTransfer` and `NotifyStackTransfer` via cached Harmony reflection with plugin ID `wire.valheim.smoothui`; no hard dependency; gracefully falls back for older versions. Only success events trigger manual visual bridge. Real source slot/icon and target slot/icon used, not stale pointer.
- Wheel DOWN: if native AddItem cloned into NEW slot -> existing quick move; if it MERGED into EXISTING stack -> new flight from original item to target. Each subsequent wheel tick triggers its own flight. Wheel UP: source is one item from opposing inventory; flight to hovered/held target + native amount pulse. RMB placing into occupied stack and double-click filling now have source-to-target flight, as do Ctrl+LMB moves into existing target stacks. Native full item moves/hotbar swaps continue native Smooth UI identity tracking; no redundant overlay.
