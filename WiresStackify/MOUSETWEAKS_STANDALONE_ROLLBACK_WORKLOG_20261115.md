## Code changes and boundaries
- **Removed entirely** from Stackify/src: `SmoothUIBridge.cs` and all SmoothUIBridge.* calls, reflection API discovery, item origin/position picking, quick flight requests and source references. Removed Smooth UI/src/QuickTransferEffects.cs (pooled flying icon layer). Original Smooth UI/src/ItemAnimationSystem.cs restored from backup `WiresSmoothUI/backup/STACKIFY_FAST_TRANSFER_20261115/ItemAnimationSystem.cs` (prior to the first performance/fast-transfer update); original Smooth UI/src/SmoothUIDriver.cs restored from git HEAD, tracked original. `git status -- WiresSmoothUI/src` clean after restore.
- Installed Smooth UI DLL is **exact saved pre-integration binary**, not a newly rebuilt / subtly different copy: SHA256 `217936BD56629A1126F0D1F257FC5EF2E05F620A8712D5F536AC48CD42089B49` from `WiresSmoothUI/backup/STACKIFY_FAST_TRANSFER_20261115/before.dll`.
- Removed Stackify half-on-idle hook `[HarmonyPatch(InventoryGui.OnRightClickItem)]` entirely, also removed `s_initialPickupRightPress` and physical WASD gate (no longer needed). If **not currently holding** inventory item, RightDown returns true and Valheim uses its native right click potion/food/use behavior, irrespective of Shift/WASD. Shift+RMB on a stack when not held DOES NOT pick it up or open split. Native Shift+left split remains.
- Renamed `HalfPickupGuard.cs` to `MouseDragGuard.cs` and `HalfPickupGuard` type to `MouseDragGuard` to describe actual behavior. A narrow Harmony transpiler still intercepts the *one* `ZInput.GetMouseButton(1)` inside vanilla `InventoryGui.UpdateItemDrag`; while already holding a stack in an open inventory, it prevents vanilla RMB from instantly cancelling the cursor item. Else native behavior unchanged. This method is source-verified in MouseTweaks' own transpiler.
- `MouseControls.Place`: now uses **native `InventoryGui.OnSelectedItem(...Modifier.Select)`** (same as MouseTweaks), temporarily using `m_dragAmount=1` for RMB, `m_dragAmount=max(1,held/2)` for Shift+RMB while holding; clamps to destination stack capacity; restores remaining held amount using native SetupDragItem where necessary. No artificial transfer visuals; native move sound, inventory access and equip/drop checks. Retains right mouse held sweep one item per newly entered slot, including crossing grids and favorited slots.
- `MouseControls.MoveViaVanilla`: direct native InventoryGui.OnSelectedItem(...Modifier.Move) for Ctrl+left (drops when no container, moves with container), still protects favorited item type and player inventory slot. Same native route as MouseTweaks.m_onSelected invocation, with Stackify user favorite policies intact. Frame/grid+slot tracking remains in event handling.
- `MouseControls.FillHeld`: on double-left, consolidate via **native Inventory.MoveItemToThis** (first within item's origin inventory and then from other open inventory) using ItemDrop.ItemData.IsSameType, matching the MouseTweaks IL behavior. The filled item remains held by the cursor via native SetupDragItem (NOT a merged stack left in its inventory as earlier Stackify implementation). Once per mouse gesture, not per-frame scanning.
- Wheel up/down still transfers one item only between player inventory and open container (not same inventory), preserving held reservation updates; optional UI bridge removed. Native inventory Changed calls and native move SFX retained. Hotbar 1-8 swap and right-click held distribution/Shift half placement retained. Only the existing InventoryGui.Update postfix for held input/hotbar/wheel is used; no new MonoBehaviour/Update/coroutine added.
- Minor native source parity: uses ItemData.IsSameType instead of comparing just shared name/quality; favorite slot guards only apply to player inventory, not coincidentally matching chest coordinates.
