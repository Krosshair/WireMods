# Stackify x Smooth UI — Minimal Compatibility Bridge (2026-11-15)

## Request and baseline
- User worked with Claude on Stackify mouse controls; wants a **tiny** update so newly added mouse inventory interactions trigger existing Wire's Smooth UI item animations, particularly moved stacks rather than instantly appearing in the destination. Absolutely NO control remapping, no changes to Smooth UI itself, no new per-frame updates, no version bump.
- Inspected currently active `src/MouseControls.cs` (225 lines, last modified 2026-11-15 09:05), SmoothUI src/ItemAnimationSystem.cs and DragAnimationSystem.cs, and native ValheimSOURCE/csharp/assembly_valheim/Inventory.cs.
- Source behavior: SmoothUI automatically subscribes to Inventory.m_onChanged (ItemAnimationSystem.BindGrid) and animates stack changes and moves when it sees the SAME ItemDrop.ItemData instance across grids. Its drag system calls `ItemAnimationSystem.NotifyDropped(item, world)` to animate a new item from the release cursor, consuming this record in the NEXT grid state refresh. Native inventory changes already trigger SmoothUI where identities are preserved. Native Inventory.AddItem(ItemData) EITHER merges into a prior stack OR inserts the exact provided ItemData clone, and always calls Changed(). Thus new clones created by Stackify's scroll/placement previously appeared rather than moving from their source. Merged stacks already pulse automatically.

## Implemented
- New small `src/SmoothUIBridge.cs` (~54 lines) optional reflection integration: only resolves `WiresSmoothUI.ItemAnimationSystem.NotifyDropped(ItemDrop.ItemData, Vector3)` when `Chainloader.PluginInfos` contains `wire.valheim.smoothui`, caches method, reuses argument array, invokes **only on actual successful inventory transfers**, gracefully disables if API changes. Zero new Harmony hooks or Update loops; Smooth UI is NOT required to run Stackify. No editing of the SmoothUI DLL.
- src/MouseControls.cs: on successful 1/half stack placement into an EMPTY slot, notify Smooth UI for the newly arrived ItemData using pointer position so it slides in. Transfers into existing stacks are not manually signaled; SmoothUI's normal Inventory.Changed stack-size pulses cover them.
- src/MouseControls.cs: on scroll DOWN transferring a new single item between player/container, capture the existing source icon's current world position (or pointer if dragging) before transfer. If native AddItem really INSERTED the cloned ItemData (`other.ContainsItem(one)`) report it to SmoothUI for its normal move animation. If native merges the clone into an existing stack, let SmoothUI's normal stack pulse handle it. Scroll UP, Shift/Ctrl vanilla selection actions, hotbar swaps, quick fill and default drag behaviors use normal Inventory.Changed and native SmoothUI item tracking; no redundant manual animation layer.
- Only Stackify MouseControls.cs edited and SmoothUIBridge.cs added. No tweaks to control layout or favorite protection, inventory transaction semantics, or icons/slot positions. Version stays 0.1.9.
