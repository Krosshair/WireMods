## 2. Handoff design, confirmed against source
- Existing cache `FindCasters` uses global `MachineHidden` to omit animated machine renderers. Existing `AddMachineGroups` adds every machine to dynamic map even while stationary. `PieceChanged` now queues affected faces and RenderDoorFace refreshes one face per frame; `RenderDirty` is existing coroutine. `LateUpdateWork` is existing built-in per-frame path.
- First implementation scope: non-windmill Smelters only. Turrets and windmills/spinning wheels stay on prior dynamic classification for correctness; generic motion-detection requires different runtime information.
- New machine initially starts STATIC if Smelter is idle (and has no active animation). Avoid putting renderer into MachineHidden and omit dynamic group. On operating START, mark hidden for new static recaptures, use existing piece-face invalidation, add dynamic caster group; while recache finishes the old static silhouette may remain alongside the moving one (no missing shadow). On STOP, delay until animation completes/eases, then remove from MachineHidden, queue static faces, keep moving caster as temporary handoff until relevant queued static faces finish. Finally remove dynamic group; old cached dynamic map is invalidated by absence of group next LateUpdate.
- Need ensure host-on/off is not identical to actual mesh moving: extra safeguard: only staticify machines whose mesh animator is demonstrably inactive (Windmill exempt); for operating state preserve dynamic classification as before.
- The new state model may require per-machine flags `InStatic`, `ReturnPending`, and deadline; do NOT add separate Update or polling. Main thread existing AddMachineGroups handles handoff completion.
