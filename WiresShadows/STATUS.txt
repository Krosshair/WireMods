# WPR one-bounce static point-light GI — 2026-11-08 prototype

Status: INSTALLED in Enngard, awaiting visual/in-game FPS validation. Not a full GI solver.
Target: Unity 6000.0.75f1, Valheim Built-in Deferred, WPR GUID wire.valheim.lightocclusion.

## User constraints honoured
- One subtle physically anchored approximate bounce per *eligible WPR-managed stationary point light* (all prefab types, not just fire), selected when its six-face cache finishes.
- Same live Unity _LightColor for the bounce, so actual RGB tint and vanilla LightFlicker brightness modulation are inherited automatically, without extra CPU intensity polling or a new light component.
- No modifications to the existing direct/point-light shadow geometry; original shadow sample is reused, and the bounced contribution is gated by its visibility to avoid immediately leaking through roof/wall geometry.
- No new C# Update, LateUpdate, FixedUpdate, coroutine or polling loop, no new shadow cubemap rendering, no additional deferred rendering pass.
- Experimental BepInEx General -> Static light one-bounce GI (default true) switches new effect without switching off WPR.

## How the one-bounce approximation works
- Existing ShadowCache static map complete (FinishMap) computes at most one Physics.Raycast-derived surface hit for each tracked stationary point light; ten fixed candidate directions, floor preferred, wall/ceiling fallback. Skip moving rigidbodies, doors, very near source collisions and unoccupied rays. StaticMask and QueryTriggerInteraction.Ignore. No probe when no plausible static collider exists.
- Store hit position (offset 4.5cm along hit normal), normal and local radius (0.75–1.95m dependent on source range). Computed ONLY when static cached map completes/refreshes; WPR's existing piece placement/removal invalidates it automatically.
- Two Vector4[96] global shader arrays publish per-slot position/radius and normal. Dirty bit marked when slot taken/released/promoted or map ready. During WPR's ordinary light fade UpdateGlobals, no per-frame reuploads or scanning if dirty bit false.
- Current WPR custom deferred shader only evaluates bounce on WPR-slotted static point lights with ready maps; an unassigned or outside-WPR source does not receive GI yet, even though its original illumination remains vanilla.
- One smooth local, direction-aware diffuse lobe: emission scales with the normal of the chosen reflecting surface; receiving surface must face that bounce, with quadratic local falloff; 0.12 coefficient before cosine/distance attenuation, intentionally faint. Uses existing source _LightColor.rgb and original point-light attenuation; follows live flicker. Existing cached primary shadow is checked/reused; no increased source intensity and no shadow opacity change.
- BIG LIMITATION: primary-source visibility gating deliberately rejects bounced light behind solid walls, preventing first-build light leaks. But true GI can illuminate certain areas hidden from the source via an unobstructed secondary path. This first prototype cannot capture such deeply occluded bounce. It is a safe single-surfel lobe, NOT high-quality physically accurate GI or arbitrary 2-bounce global illumination.
- The bounce lobe remains within original point-light deferred volume and WPR slot limit; no extra rendering for new lights, no extra camera or costly per-frame proximity search.
