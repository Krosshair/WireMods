# Wire's Acoustics — Full ValheimSOURCE Audio Coverage Audit
2026-11-09 | source-integrated release design | STATUS: AUDIT ONLY, existing Enngard DLL unchanged

## Aim
A genuinely integrated full implementation, not arbitrary coverage of everything that happens to be an `AudioSource`. Support every *audible WORLD source* with appropriate acoustics, while expressly excluding music, UI, cinematics and non-spatial informational cues unless intentionally handled. Full ValheimSOURCE improves our knowledge of built-in paths, but the claim "zero missing links" must be proven with a coverage ledger and runtime instrumentation; third-party sources and platform DSP cannot be inferred from the game's C# alone.

## Native pipeline crosscheck (verified from ValheimSOURCE/csharp/assembly_valheim)
- ZSFX.Play (lines 294-335): normal game sound starts after AudioMan.RequestPlaySound accepts it, clip randomization and AudioSource.Play; WiresAcoustics Travel patches precisely this accepted call. ZSFX.CustomUpdate (174+) updates loop reverb and source pitch/volume; existing Occlusion.UpdateReverb hooks only sounds that actually call it. ZSFX.PlayOnAwake can be delayed; accepted-play hook catches actual starts.
- FootStep.DoEffect (275-313): instantiates EFFECT PREFABS and annotates source with network creator ID; sound is normally a ZSFX on the effect object, not a call to PlayOneShot. FootStep's actual effects/wood/stone OGG assets can be audited offline. Capturing clip/pitch alone does not determine PCM crackle.
- EffectList.Create (37-110): instantiates many game-world FX prefabs and supports parent/follow flags. Follow.Create postfix covers many but not unrelated prefab instantiation. Prefabs/ZNetScene.Awake pre-attaches AcousticFilter to some asset prefabs; Spawned scans Location and DungeonGenerator.PlaceRoom. These are NOT a formal complete guarantee for arbitrary dynamic AudioSource added at runtime.
- AudioMan.Awake (202-249) directly adds and starts persistent ocean, wind, 2D biome ambient sources; existing Ambience and Ocean handle them. AudioMan.UpdateRandomAmbient (358-399) instantiates randomAmbientPrefab beneath AudioMan and calls ZSFX.Play; existing Ambience treats these as 2D world ambience when enclosed. AudioMan.UpdateLavaAmbient (~415-444) ALSO instantiates the SAME randomAmbientPrefab under AudioMan at a REAL LAVA POSITION, so the current `parent==AudioMan.transform && enclosure>=.35` heuristic in Occlusion.Run treats its 3D lava noise as generic ambience indoors. This is a SOURCE-PROVEN classification conflation. Fix by labeling provenance from native producer methods/events instead of using only parent+enclosure; do not classify every AudioMan child as 2D birds.
- AudioMan.UpdateAmbientLoop (535-565): manages global ambient 2D loops including forest bird loop; mod deliberately processes as ambience. AudioMan.RequestPlaySound (738+) gates sound concurrency; Travel now hooks only accepted play.
- ShipEffects.FadeSound (138-155) calls `AudioSource.Play` DIRECTLY without ZSFX. AudioMan shieldHum source also calls `AudioSource.Play` directly. MusicMan (~451) and MusicLocation (~61) call Play directly but MUST remain music, not world occlusion. This exposes the limitation of any ZSFX-only approach and why a blanket AudioSource.Play hook would be harmful.
- CharacterAnimEvent.Awake turns loop audio GameObjects on; ZSFX's existing start-on-awake generally covers their runtime audio but confirm exported specific prefab ancestry and AudioSource ownership.
- Valheim C# has 20 `.Play(` sites across 12 files (includes non-audio particle/video invocations); no `.PlayOneShot`, `.PlayDelayed`, `.PlayScheduled`, `.PlayClipAtPoint` source hits. This is the *decompiled base game C#*, not Unity components' native auto-start paths or modded code.

## Coverage ledger to build (each row must be source-mapped, tested in-game)
1. Game-world one-shot via ZSFX: creatures, attacks, doors, containers, footsteps, effects, terrain, fire. Hook accepted playback event, occlusion/path/doppler/lifetime, original clip continuity.
2. Game-world looping via ZSFX: fires, machinery, character loops, weather-created loops, dungeon loops; moving-source updating and invalidation.
3. Non-ZSFX direct AudioSources: ship wakes, shield hum, other audio prefabs, dynamic AudioSource consumers; route by mixer group + source provenance, not blind Play hijack.
4. Global biome ambience: wind, forest bird loop, ocean, rain; process 2D sources by indoor enclosure and opening position without converting MUSIC into SFX.
5. Random 2D environmental events: real sound source `AudioMan.UpdateRandomAmbient`. Note sound may originate on a spatial random point and must be handled by intended semantics of biome ambience. Refresh while playing on room changes.
6. Random PHYSICAL lava events: distinct `AudioMan.UpdateLavaAmbient` source semantics even though same parent/prefab; preserve real position, wall occlusion, physical rolloff and direction.
7. Positional animal events: `sfx_seagull_idle` is a real 3D world ZSFX; do NOT assume it is the forest ambient loop. Current initial ray through >7 walls correctly reports 0.28 gain/500Hz but final routed/active state remains unknown. Diagnose final DSP and mixer route rather than lower all seagull volume.
8. Owned/UI sounds: game cues/music/FejdStartup/menu/video leave authored unless explicit; player 2D-to-3D conversion only where ownership is known; equipped item events maintain relevant actor/source follow.
9. Procedural dungeons, streamed locations and modded effects: verify on-spawn attachment, zone deletion, original reverb and lifecycle. Third-party mods can instantiate totally new AudioSources after prefab registration.
10. Multiplayer and voice: player sounds and ProximityVoiceChat through native and plugin-specific paths, source cleanup, attenuation, player teleports and disconnects.
11. Runtime audio assets: inspect all exported OGG clips' sample boundary, format, pitch/randomization and import settings. C# alone cannot show a bad waveform or OS audio-driver underrun.
12. Underwater/shore, mist, wind, waterfalls, portals, weather, variable geometry: reverb/occlusion/near/far and source ownership all need actual scene tests.

## Newly confirmed audit issues, ordered
- High: native producer provenance is ambiguous: Lava random ZSFX shares AudioMan parent + randomAmbientPrefab with global random bird calls. Current parent heuristic wrongly converts physically located lava noise to ambient when enclosed; address with event-based producer-specific registration, not name substring.
- High: only UpdateReverb is hooked for most ZSFX occlusion refresh. Vanilla loop reverb update is conditional on `m_distanceReverb` and `m_audioSource.loop`, while mod Recheck skips loop SFX (`if (f.Kind==Sfx && (src.loop || now-f.StartedAt <.4)) continue`). Therefore a ZSFX LOOP with vanilla m_distanceReverb=false may never receive *continuous* geometry occlusion refresh. Compare each prefab's authored `m_distanceReverb` and runtime loop status; source-proven potential gap, not verified sonic symptom.
- High: stale outdoor animal attenuation cannot be distinguished from final game mixer signal by initial `Muffle` target alone; observe final filter callback state and duplicate source routes.
- High: wood/stone footstep clicks persist after previous DSP/transpiler fixes; no evidence an arbitrary fade helps. Need decode original OGG and compare with a loopback capture of the mod enabled vs disabled (and other mods), exact pitch/clip selection. `FootStep.DoEffect` confirms playback is instantiated from effect prefabs.
- Medium: standard non-ZSFX ship and shield hum source registration and provenance could be missed by existing prefab-only or event-only coverage; inspect exported prefabs and live registration. Do not presume missing unless runtime trace shows it.
- Medium: dynamically instantiated arbitrary mod AudioSource bypasses all built-in paths. Safe opt-in plugin API for registering 3D/ambient/voice sources and a lightweight event hook for known spawn routes can reduce blind spots without introducing polling.

## Required implementation design
- Categorize producer at source creation: ZSFX world, AudioMan random ambience, lava positional, direct scene/ship audio, global ambient, local player, voice, music/UI. Separate *actual source identity* from acoustic category. Never decide purely from `AudioMan` parent and indoor enclosure.
- Lifecycle contract: `register -> accepted play -> locate listener/owner -> classify -> direct/alternate path -> process -> stop/recycle`, with explicit disable/scene cleanup; each native route should have a mapping to that contract.
- RT constraints: zero allocations/Unity APIs/logging/locks in OnAudioFilterRead; use bounded buffers, atomic handoff and monitored callback peaks. Keep the existing game's centralized updates and short event callbacks, avoid new high-frequency world scans.
- Deterministic PCM fixtures for footstep clips; sample rate/channel/buffer transitions; original audio still belongs to game and stays local; do not publish ripped assets.
- Verification: source symbol/IL check, prefab-route audit, debug-only coverage counters with zero/missing reasons, runtime fixed tests (interior/exterior, wood/stone, seagulls, forest birds, lava, dock/ship, dungeon, modded sound and voice), vanilla A/B with same ambient conditions, performance timings and rollback build.
